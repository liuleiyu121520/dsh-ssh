## dsh 桌面端启动崩溃修复（web boot: dsh-ssh-terminal: failed）
- 根因：cordis 4.x 访问**未在 inject 声明**的服务属性会抛 `cannot get property "X" without inject`（不是返回 undefined）。`src/client/launchpad.js` 的 `const locale = ctx.locale` 让客户端 apply 炸掉 → fiber FAILED → 整个 app 起不来。
- 修法：`ctx.locale` → `ctx.get('locale')`（非抛访问器）；**不能**把 'locale' 加进 inject（服务缺失会变 pending，同样激活失败）。commit 8b39f7b。
- 定位手段：node 复现 harness（真 cordis + 真 cordis-plugin-loader + 真 client-modules + vm sandbox 加载真 lib/client.js），已固化为 `scripts/client-boot.repro.mjs`（退出码 0 = 激活通过）。教训：仓库既有单测全跑假 ctx 替身，这类真机崩溃单测永远抓不到。
- 验证：85/85 单测、repro 正负对照、真机 `open -a "DeepSeek Harness"` 冷启动 4 分钟零新崩溃日志。

## 修复：prepared LLM call config changed before adapter dispatch —— commit 07ae69e

## 修复：finish reason 形状错误导致“输入了没反应” —— commit（本轮）
- 真机症状：发消息后用户气泡在，助手侧零响应、无错误、无“思考中”。

- 教训：测试里的 chunk 形状必须照真契约写——前两轮测试用字符串 reason 所以全绿，真机第一次跑就栽。

## 修复：“此应用加载失败”（xterm 6 onFocus）+ marker 两行竞态 —— commit 8df4817
- **“加载失败”根因**：xterm 6.0 公开 Terminal 类（src/browser/public/Terminal.ts）**移除了 onFocus**（内部 CoreBrowserTerminal 有但没暴露）。store.js 无条件 `term.onFocus()` → 每次开会话抛 TypeError → 启动台 AppBoundary 兜住 → “此应用加载失败”。修：特性检测 + `term.textarea` DOM focus 事件兜底。jsdom 状态驱动渲染（mock fetch 驱动 store 走完整对话流）复现并验证修复。
- **marker 竞态**：executeInSession 原两次 send（命令一行 + printf 一行），真终端上 readline 偶尔吞掉第二行换行 → printf 永不执行 → 必超时（E2E 12/13↔13/13 反复跳）。修：**单行合成** `cmd; printf marker "$?"` + 超时补救（Ctrl+C 后补发 marker 行收输出）。E2E 三连跑 13/13 稳定。
- 方法论沉淀：/tmp/render-repro/ 的 jsdom 渲染 harness（真 React 18 + 真 bundle + mock fetch 驱动 store）是抓“视图渲染抛错”类问题的利器——client-boot.repro 只覆盖激活，不覆盖渲染。

## 根因：60s 硬看门狗把"健康的长思考"掐了（原生能答、右栏必挂）—— 本轮
- 用户反馈：同一个模型，dsh 新建任务里能答，右栏面板"一直思考中"。上一轮把原因归到"未登录通道"是错的——通道没问题，是我们自己的两条假设错了。
- 事实链（读真 adapter 源码 `~/.dsh/profiles/desktop/node_modules/dsh-our-free-model/src/adapter.js` + harness `packages/llm/llm/src/types.ts`）：
  1. `StreamChunk` 有 `reasoning-delta`；`consumeStream` 只认 `text-delta`，**整个思考期一个 SSE 事件都不发**；
  2. combo 通道（`runCombo`/`commitsAnswer`）在出首个正文前会把 reasoning 增量**整段缓冲**，连 reasoning 都收不到；
  3. 于是 60s 硬超时必然误杀——原生对话没有看门狗，所以它能等到答案。看门狗本身是上一轮加的，属于自伤。
- 修：①`consumeStream` 转 `reasoning` 事件，右栏渲染"思考过程"折叠框；②看门狗改两档：60s 只打 `slow` 提示、180s 才断开；任何事件（含 reasoning）都撤提示并归零；③`runTurn` 客户端已给 provider+model 时**不再先跑 describeModels()**（列清单可能碰账号/网络，挡在第一个事件之前），prepareCall 失败才回退清单一次；④新增 `accepted` 首帧。
- 顺手修掉一个潜在死锁：暂停态（finish{tool-call}）原来复用 `streaming:true`，流一结束又回 false，导致输入框可发新消息（历史里留下无结果的 tool-call，wire 必拒）。新增 `pending` 独立字段锁输入框，`resolveToolCall` 只挡 streaming。
- 测试：store-watchdog 重写为两档 + "reasoning 算有动静"；新增 store-toolpause（暂停→执行→续跑）；chat.test 补 reasoning 透传与"跳过清单"。112/112。
- 坑：`tests/chat.test.js` 注释里有个裸 NUL 字节（`printf marker "\0"`），git 一直把它当二进制、diff 看不见——已换成转义文本。
