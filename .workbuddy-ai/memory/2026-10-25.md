## 更正：不存在"禁止 import dsh 内部包"的铁律（2026-10-25 晚核实）
- 之前多次告诉用户"第三方插件禁止 import dsh 内部包"——**错**。官方升级指南 `docs/upgrade-guide/v0.2.1-alpha.1/terminal-command-labels/guide.md` 原文："This affects **custom UI plugins** that render `TerminalBlock`"，即官方明确支持第三方 UI 插件使用 `@deepseek-ai/dsh-client-ui-primitives`。兄弟插件 dsh-launchpad 已在用（`src/client.js` 运行时 `require('@deepseek-ai/dsh-client-ui-primitives')` + try/catch + 自绘兜底，且**不在 package.json 声明依赖**——这是规避版本漂移的正确姿势）。

## 接上启动台 onTeardown（v1.2 新协议）
- 用户提示：启动台协议变了，关卡片会通知插件销毁。核实 `dsh-launchpad/src/page.js`：`viewProps = {appId, app, close, onTeardown, open, t, active}`；`onTeardown(handler)` 返回注销函数，handler 收 `{reason}`，**同步**执行；触发点 = `closeTab()` 第一步（用户点 ✕ 或插件自己 `props.close()`，reason `tab-closed`）与启动台整体卸载（reason `launcher-disposed`）。
- 此前本插件完全没接（SshAppView 连 `active` 都丢给 `_active`）→ 关卡片只是看不见，Host 侧 SSH 连接、客户端 xterm + EventSource 全成孤儿。
- 实现：`store.teardownAll(reason)`——同步：stopPolling + 逐 sid `destroyRuntime()`（ES/xterm/DOM 全收）+ 状态归零（tabs/activeSid/sessions/chats）；异步：逐个 `POST /close` fire-and-forget（协议要求 handler 同步返回，关闭动画不能等 HTTP）。App.jsx 用 `useEffect` 注册，老启动台不传该 prop 时防御性跳过；顺带把 `active` 用对（隐藏停轮询、显示再开，两个函数都幂等）。
- 测试 154/154：新增 tests/store-teardown.test.js 4 条（每会话一次 /close、状态归零、轮询停、幂等）；jsdom 端到端（/tmp/mdcheck/run4.mjs，模拟启动台调 handler）验证注册与关闭请求。
- 坑：测试里 openSession 依赖 /open 返回 sid，桩漏了会静默失败（showToast 后 return null，tabs 不建）。

## 修复：不再自动开标签 + 连不上时把原因写进终端
- 用户报两件事：①第一次进 SSH 卡片就自动多出「腾讯云 #1」标签；②"双击连接不上了"（截图里终端全黑）。
- **①的根因是配置合并语义**：`autoOpenFirst` 写成 `=== false` 才跳过；而 profile 的 `~/.dsh/profiles/desktop/cordis.patch.yml` 里 `- id: dsh-ssh-terminal / config: {enabled: true}` 会**整块替换** config（vendor/include/src/index.ts 的 applyEntryPatches 就是 `target[key] = value`，不是深合并）→ bundle patch 的 `autoOpenFirst: false` 被抹掉 → 字段缺席 → 自动开。改成 `!== true` 才生效。**通用教训：dsh patch 的 config 是替换不是合并，默认值必须落在安全侧。**
- **②不是插件 bug**：真机 `/open` 200、会话状态 `error: Connection lost before handshake`。裸 socket 探针（python）：TCP connect 1-5ms 成功，之后 **~5.0s 收到 FIN、零字节 banner**；系统 `ssh -v` 同样 `kex_exchange_identification: Connection closed by remote host`；ping 通、80/443 通 → 服务端/云安全在拦本机 IP（典型 fail2ban 类爆破保护），需在服务器侧解封。
- 但暴露了产品缺陷：SSH 失败时缓冲零字节，客户端收到 `event: exit` 只 close()，黑屏静默 → 用户以为卡住。现 store.js 新增 `writeFailure()`：exit 帧带 reason 就写红字「✗ 连接失败：<reason>」，首屏失败（rt.seq===0）再补一行排查提示。
- 顺带对齐双击语义（注释本来就这么写）：`handleOpenTab` 先找该主机 open/connecting 的会话，有就聚焦、没有才新建；行内 `+` 改走新的 `onNewTab`（总是新建），两者不再混用。
- 验证：单测 159/159；client-boot.repro 通过；假 ssh2 服务端（/tmp/dsh-ssh-diag2.mjs，进程内 ssh2.Server + 假 shell）端到端确认「激活后会话=0」且连接成功时 SSE 真出字（`FAKE_SHELL_READY\r\n$ ECHO HI`）。
